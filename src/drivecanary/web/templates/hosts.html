Adding a host

A host is monitored one of two ways. Pull: the hub reaches it over ssh, hourly; nothing runs on the host in between. Push: an agent on the host reports to the hub, hourly and two minutes after the host boots; for a host that is only up on demand, and for the hypervisor this VM runs on, which should accept no key of the hub's.

Pull

Three steps. The first runs on your workstation, from a checkout of this repository, over your own ssh to the host (as root); the other two run on this VM.

1. Workstation: the drivecanary user, the probe and the gate, the sudoers line, and this hub's key bound to the gate. It ends by printing the host's key fingerprint.

deploy/host/install-host.sh HOST --hub-ip {{ hub_ip or 'THIS-VM-IP' }} \
  --hub-key '{{ hub_key or 'ssh-ed25519 AAAA... drivecanary-hub' }}'
{% if not hub_key %}

The hub's public key is not where the page can read it yet (it is copied on the next collection): sudo cat {{ cfg.ssh_dir }}/id_ed25519.pub

{% endif %}

Add --target root@HOST.domain if your ssh config does not already say how to reach it.

2. Here: the host's row and its pinned key. Add --tz ZONE only for a host that is not in {{ cfg.collect.default_tz }} and does not say so itself.

drivecanary host add HOST --address HOST.domain --fingerprint SHA256:...

3. Here: the first collection. The host goes from pending to ok and its smartd history is pulled from the start.

drivecanary collect --host HOST

Push

1. Here: the host's row. It prints the host's token, once, and the command for step 2.

drivecanary host add HOST --transport push

2. Workstation: the drivecanary user, the probe, the agent with its token, and its timer. It ends by sending the first report.

deploy/host/install-host.sh HOST --push --hub-url http://{{ hub_ip or 'THIS-VM-IP' }}:{{ cfg.ingest.port }} --token TOKEN

An OPNsense router is a push host too, by the same two steps (use --target root@ROUTER). There the agent runs from root's cron, and smartctl comes from the os-smart plugin.

A lost token: drivecanary host token HOST makes a new one, and step 2 again installs it. Moving a host from one way to the other: drivecanary host set HOST --transport push (or pull), then the matching install.

Add --self-tests to either install to have smartd give every drive a short self-test each month and a long one each year, each drive on a date of its own; --no-self-tests takes that out again. The host's page then says when each is next.

The install keeps what it was given, in ~/.config/drivecanary/hosts/HOST on the workstation, so running it again is deploy/host/install-host.sh HOST, and for every host at once deploy/host/install-host.sh --all. That is how a probe upgrade or a repair is rolled out. A host that is away for months: drivecanary host set HOST --state paused; gone for good: --state retired (history is kept). What each failure class on a host's page means is in deploy/README.md.
